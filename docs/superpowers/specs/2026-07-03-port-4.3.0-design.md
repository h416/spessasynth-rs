# 設計: spessasynth_core 4.3.0 の Rust 版への反映

日付: 2026-07-03
ステータス: 承認済み

## 背景

本プロジェクトは spessasynth_core-4.2.0(TypeScript)を Rust に移植したもの(ファイル単位・関数単位で同一になるよう移植)。spessasynth_core-4.3.0 がリリースされたため、その変更を Rust 版に反映する。

- 4.3.0 ソース: `tmp/spessasynth_core-4.3.0`
- リリースノート: https://github.com/spessasus/spessasynth_core/releases/tag/v4.3.0
- 4.2.0→4.3.0 の diff 規模: 約 7,000 行・112 ファイル

### 4.3.0 の主な変更

- **構造の大再編**: `audio_engine/engine_components/`・`engine_methods/` を廃止し、`channel/`(MIDIチャンネル処理)、`voice/`(ボイス・DSP)、`system_exclusive/`(roland/yamaha/universal)、`parameters/` に再編
- **挙動変更**: 位相ベース LFO への切り替え、ボリュームエンベロープの性能改善、NRPN 順序修正、モジュレーションホイール倍率修正、ループなしサンプル・アタック部のクリック修正、data entry の LSB 保持バグ修正、EFX センドレベル修正、キー番号オーバーライド修正、ドラム精度改善
- **削除**: 東方カスタムビブラート機能
- **その他**: tsdown への移行、preset_selector → midi_patch 改名、MIDI 解析メソッドの抽象化・共通化

## 決定事項

| 項目 | 決定 |
|---|---|
| 成功基準 | TS 4.3.0(deterministic random パッチ適用)と Rust の WAV が `tools/batch_compare_impl.py` の PASS 基準で一致 |
| 検証範囲 | `sample/midi/` 全9曲 |
| 移植範囲 | XMF / SF3(Vorbis) を除く全ファイルミラー(従来方針の継続) |
| アプローチ | 構造先行の二段階(先に構造再編のみ・出力不変を検証、次に挙動移植) |

**WAV 一致の許容誤差**: 完全一致(バイナリ一致)は f64/f32 丸め差により不可能。過去の 4.1.0→4.2.0 移植でも ±1 程度の int16 サンプル誤差が残るのが実績。判定は `batch_compare_impl.py` の PASS 基準(チャンネルごとに RMS diff < 10 かつ max abs diff < 500)を用い、実績目標は max diff ±1 程度とする。Rust 同士のリファクタ検証(フェーズ1)は完全一致を要求する。

## 全体構成

作業は3フェーズで構成する。

| フェーズ | 内容 | 比較対象 | 完了条件 |
|---|---|---|---|
| フェーズ0 | 下準備 | TS 4.2.0 vs 現行 Rust | 全9曲 PASS(ベースライン健全性の記録) |
| フェーズ1 | 構造再編(挙動不変) | 再編後 Rust vs 現行 Rust | 全9曲 完全一致 |
| フェーズ2 | 挙動移植 | Rust vs TS 4.3.0 | 全9曲 PASS 判定 |

## フェーズ0: 下準備

1. **ベースライン確認**: 既存の `tools/batch_compare.sh`(TS 4.2.0 vs 現行 Rust)を実行し、全9曲 PASS を確認・記録する。問題があれば 4.3.0 作業前に報告する。
2. **deterministic random パッチの再適用**: `tschange/note_on_deterministic_random_pan.patch` は `engine_methods/note_on.ts` 対象だが、4.3.0 ではファイルが `channel/note_on.ts` に移動しているため、パッチを新パスに合わせて手直しして適用する。random 呼び出し箇所が変わっていれば、同じ決定的アルゴリズムで書き直す。修正版パッチは `tschange/` に 4.3.0 用として保存する。
3. **TS 4.3.0 の実行確認**: `examples/midi_to_wav_node.ts` が tsx で実行できることを確認する(tsdown 移行済みのため実行方法の変化に注意)。
4. **比較スクリプトの 4.3.0 対応**: `tools/batch_compare.sh` の TS 実行パスを `tmp/spessasynth_core-4.3.0` に、TS 出力先をバージョン別(`sample/result/ts430/` など)に更新する。スクリプト内の短縮 MIDI 名(EarthDay 等)と `sample/midi/` の実ファイル名の対応も確認する。
5. **リファレンス WAV 生成**: TS 4.3.0 で全9曲を生成する。
6. **Rust ベースライン WAV 生成**: 現行 Rust 版でも全9曲を生成・保存する(フェーズ1の「出力不変」検証用。手順1の出力を流用可)。

## フェーズ1: 構造再編(挙動不変)

Rust のファイル配置を 4.3.0 の TS レイアウトに合わせて移動・分割する。コードの中身は移動に伴う `use` パス修正のみで、ロジックは一切変更しない。

### synthesizer/audio_engine の主な対応

| 現行 Rust(4.2.0 構造) | 移動先(4.3.0 構造) |
|---|---|
| `engine_components/midi_channel.rs`, `drum_parameters.rs`, `dynamic_modulator_system.rs` | `audio_engine/channel/` |
| `engine_methods/note_on.rs`, `portamento_time.rs`, `program_change.rs`, `stopping_notes/note_off.rs` | `audio_engine/channel/` |
| `engine_methods/controller_control/`(controller_change, data_entry 系, reset_controllers) | `audio_engine/channel/`(data_entry は `data_entry.rs` に統合、awe32 → `awe32_nrpn.rs`、reset_controllers → `reset.rs`) |
| `engine_components/dsp_chain/render_voice.rs` | `audio_engine/channel/render_voice.rs` |
| `snapshot/channel_snapshot.rs` | `audio_engine/channel/channel_snapshot.rs` |
| `engine_components/voice.rs`, `voice_cache.rs`, `compute_modulator.rs`, `unit_converter.rs` | `audio_engine/voice/` |
| `engine_components/dsp_chain/`(lowpass_filter, modulation_envelope, volume_envelope, wavetable_oscillator) | `audio_engine/voice/` |
| `engine_components/dsp_chain/lfo.rs` | 4.3.0 では独立ファイル廃止(位相ベース化で voice 側へ統合)。フェーズ1では暫定的に `voice/lfo.rs` として残し、フェーズ2で統合 |
| `engine_methods/system_exclusive/`(handle_gm/gs/xg, helpers) | `audio_engine/system_exclusive/`(universal / roland / yamaha / system_exclusive に対応付け) |
| `engine_components/controller_tables.rs`, `master_parameters.rs` | `channel/parameters/` および `audio_engine/parameters/`(TS の midi.ts / system.ts に対応) |
| `engine_components/modulator_curves.rs` | `soundbank/basic_soundbank/modulator_curves.rs`(TS 側でも soundbank へ移動) |
| `engine_components/`(key_modifier_manager, sound_bank_manager, synth_constants, synth_processor_options)、`snapshot/synthesizer_snapshot.rs` | `audio_engine/` 直下 |

### synthesizer 以外の再編

- `midi/`: `read/` `write/` サブディレクトリ化(midi_loader → read/ 配下)、`midi_tools/` の改名・追加(used_keys_loaded → used_programs_and_keys、新規: apply_snapshot, parameter_tracker, modify_midi, midi_utils)
- `soundbank/`: preset_selector → midi_patch 改名、basic_global_zone 廃止、modulator_curves 受け入れ
- `sequencer/`: play / song_control → load_new_sequence / set_time_to 再編

詳細な全ファイル対応表は実装計画(writing-plans)で確定する。

### フェーズ1の検証

再編完了後、`cargo build` + 全9曲生成 → フェーズ0手順6のベースラインと**完全一致**を確認する。差が出たら移動ミスなので即修正する。

## フェーズ2: 挙動移植

再編済み Rust と TS 4.3.0 がファイル1対1で対応した状態から、各ファイルの diff を移植する。依存の少ない順に機能クラスタ単位で進める。

1. **utils / soundbank**: RIFF・SF2 読み込みの変更、modulator_curves 移動先の内容更新、midi_patch(旧 preset_selector)
2. **midi**: read/write 再編後の内容、新規 midi_tools(apply_snapshot, parameter_tracker, modify_midi, used_programs_and_keys, midi_utils)
3. **sequencer**: load_new_sequence, set_time_to, process_event / process_tick の変更
4. **synthesizer/channel**: NRPN 順序修正、data entry LSB 保持バグ修正、モジュレーションホイール倍率修正、キー番号オーバーライド修正、ドラム精度改善
5. **synthesizer/voice**: 位相ベース LFO への切り替え(LFO1/LFO2 ピッチデプス修正含む)、ボリュームエンベロープの性能改善、ループなしサンプルのクリック修正、アタック部クリック修正、東方カスタムビブラートの削除
6. **system_exclusive / effects**: SysEx 対応拡大(roland/yamaha/universal)、EFX センドレベル修正

各クラスタ完了時に `cargo build` と全9曲の生成が通ることを確認する(中間状態では TS 4.3.0 との WAV 一致はまだ期待しない)。全クラスタ完了後に `tools/batch_compare.sh`(4.3.0 版)で全9曲 PASS を確認する。

### 移植時の規約(CLAUDE.md 準拠)

- コメントは英語で記述する
- `gen` は Rust の予約語のため `r#gen` を使う
- `[f32]` / `Vec<f32>` 配列以外は f64 で計算し、配列代入時のみ f32 にキャスト。配列から取り出したら即 f64 にキャスト
- MIDI チャンネルは 0 base(ドラム = ch9)
- deterministic random は TS 側パッチと同一アルゴリズムを維持する

## 不一致時のデバッグ戦略

`tools/measure_analysis.py` / `segment_analysis.py` で差分の大きい時間帯と MIDI イベントの相関を取り、`tools/isolate_channel.py` でチャンネルを絞り込んで原因ファイルを特定する(4.1.0→4.2.0 移植で実績のある手順)。

## リスク

- **位相ベース LFO**: 全曲の出力に影響する変更で、フェーズ2最大の不一致リスク。TS 実装(数式・位相初期値・更新タイミング)を関数単位で忠実に写す。
- **ボリュームエンベロープ改善**: 計算順序の変化で丸め誤差が変わりうる。±1 許容内に収まるかを実測で確認する。
- **deterministic random パッチの再適用**: 4.3.0 で note_on 内の random 使用箇所が変わっている場合、TS/Rust 双方で同じ決定的アルゴリズムに揃え直す。
- **TS 4.3.0 の実行環境**: tsdown / ES2022 移行で examples が tsx でそのまま動かない可能性。フェーズ0の最初に検証する。
- **スコープ外ファイルの混入**: 4.3.0 の新規ファイルのうち XMF / SF3(Vorbis) 関連はスキップする(従来方針)。
